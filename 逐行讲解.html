🎮 飞机大战 — 逐行代码讲解

每一行是什么意思、为什么这样写、删掉会怎样——答辩前把它看熟。

第 1 行

#define NOMINMAX

这行是干嘛的？定义 NOMINMAX 宏。告诉后面要引入的 Windows 头文件：不要把 min 和 max 定义成宏。因为 Windows 的 <windows.h> 里有 #define min(a,b) ((a)<(b)?(a):(b))，如果这个宏进来了，代码里所有的 min 函数调用都会被替换成宏展开，轻则语法错误，重则莫名其妙的行为。这行必须在所有 #include 之前。

答辩被问："Windows SDK 里 min/max 是宏，会和我的代码冲突，所以用 NOMINMAX 禁止它们。"

第 2-7 行

#include <graphics.h> // EasyX 绘图库 #include <stdio.h> // sprintf_s 格式化字符串 #include <stdlib.h> // rand() 随机数, srand() 随机种子 #include <time.h> // time(NULL) 获取当前时间——当随机种子 #include <math.h> // sinf() cosf() 三角函数——粒子360度飞溅 #include <tchar.h> // TCHAR _T()——让字符串在Unicode/MBCS下都能编译

graphics.h 是什么？EasyX 的主头文件。里面声明了 initgraph(打开窗口)、solidcircle(画实心圆)、solidrectangle(画实心矩形)、outtextxy(输出文字)、FlushBatchDraw(双缓冲提交) 等所有绘图函数。没它啥都画不了。

tchar.h 是什么？Windows 提供的字符集兼容头文件。里面定义了 TCHAR 类型和 _T() 宏。当项目设成 Unicode 时，TCHAR 自动变成 wchar_t，_T("你好") 变成 L"你好"；当项目设成多字节时，TCHAR 变成 char，_T("你好") 就是 "你好"。写一次代码，两种字符集都能编译。

第 9-10 行

#define WINDOW_WIDTH 720 // 窗口宽度：720像素 #define WINDOW_HEIGHT 960 // 窗口高度：960像素（竖屏比例，手机常见比例9:12≈3:4）

为什么用 #define 不用 int？宏在编译前由预处理器直接替换成数字，不占内存。改窗口大小只需改一处。而且在定义数组大小时，C 语言要求用常量表达式，#define 是编译期常量，可以用于数组声明。

第 11-19 行

#define MAX_BULLETS 100 // 子弹池大小：同时最多100颗子弹在屏幕上 #define MAX_ENEMIES 50 // 敌机池大小：同时最多50架敌机 #define MAX_PARTICLES 200 // 粒子池大小：同时最多200个爆炸粒子 #define MAX_STARS 80 // 背景星星数量：80颗星星构成星空 #define PLAYER_SPEED 6 // 玩家每帧移动像素数 #define BULLET_SPEED 10 // 子弹每帧往上飞的像素数 #define SHOOT_CD 8 // 射击冷却帧数：按空格后等8帧才能再射 #define INVINCIBLE 90 // 无敌帧数：被撞后90帧不受伤害（约1.5秒） #define MAX_LIVES 3 // 最大生命值：3条命

SHOOT_CD=8 是要干嘛？没有冷却的话，按住空格每帧都会生成子弹，一秒就能射出60发，纯属子弹海——不好看也没技术含量。8帧冷却的意思是发完一轮子弹后至少要等8帧才能发下一轮，节奏刚刚好。

INVINCIBLE=90 => 1.5秒怎么算的？主循环末尾 Sleep(16) ≈ 每帧16毫秒 → 每秒约60帧。90帧 ÷ 60 = 1.5秒无敌时间。

第 21-27 行

#define ENEMY_SMALL 0 // 小敌机标识 #define ENEMY_MEDIUM 1 // 中敌机标识 #define ENEMY_BIG 2 // 大敌机标识 #define STATE_MENU 0 // 状态-菜单 #define STATE_PLAYING 1 // 状态-游戏中 #define STATE_GAMEOVER 2 // 状态-游戏结束

为什么不用 enum？用 enum 也可以——enum { ENEMY_SMALL, ENEMY_MEDIUM, ENEMY_BIG }。用 #define 是 C 语言的传统写法，更直观。答辩时提到"可以用 enum 改进"说明你有工程思维。

第 29 行

#define KEY_DOWN(vk) ((GetAsyncKeyState(vk) & 0x8000) ? 1 : 0)

这是整个游戏最黑的一行，拆开讲：

GetAsyncKeyState(vk) 是 Windows API 函数，接收一个虚拟键码（比如 'A' 就是 65，VK_SPACE 就是 32），返回一个 SHORT 类型的值（16位整数）。这个值的最高位（第15位，即 0x8000）表示"这个键从上次调用后有没有被按过"。如果按了，最高位=1。

& 0x8000 是按位与操作——只保留返回值的最高位，其他位全部清零。结果要么是 0（键没按），要么是 0x8000（键按了）。

? 1 : 0 三目运算符——非零就返回 1，零就返回 0。所以最终 KEY_DOWN('A') 的返回值：按着=1，没按=0。

为什么不直接用 _kbhit()？_kbhit() 只能检测"有没有键被按下"，不能检测"A键是不是正在被按着"。射击游戏需要能检测按住不放的状态——按住空格连续射击、按住W持续向上飞。

第 32-36 行 — 五个结构体

typedef struct { float x,y; int w,h; int lives; int invTimer; int shootTimer; } Player; typedef struct { float x,y; int w,h; int active; } Bullet; typedef struct { float x,y; int w,h; int speed; int hp; int type; int active; } Enemy; typedef struct { float x,y; float vx,vy; int life,maxLife; int active; } Particle; typedef struct { float x,y; int speed,bright; } Star;

为什么坐标用 float 不用 int？float 可以表示小数位置。比如每帧移动 1.5 像素——int 做不到（要么 1 要么 2），float 可以。画图时再转成 int。所以移动是平滑的，不会一跳一跳。

为什么 Player 没有 active？玩家只有一架，永远活跃，不需要对象池管理。Bullet/Enemy/Particle 是多实例的，才需要 active 标记。

vx, vy 为什么是 float？粒子速度有小数分量（cosf/sinf 的结果是 -1.0~1.0 之间的小数），必须用 float 才能存住精度。

Star 为什么没有 active？80颗星星永远存在、永远活跃，不需要管理生命周期。直接全部遍历全部画。

第 39-44 行 — 全局变量

Player g_player; // 玩家飞机（全局唯一） Bullet g_bullets[MAX_BULLETS]; // 子弹数组：100个槽位的对象池 Enemy g_enemies[MAX_ENEMIES]; // 敌机数组：50个槽位 Particle g_particles[MAX_PARTICLES]; // 粒子数组：200个槽位 Star g_stars[MAX_STARS]; // 星星数组：80颗 int g_score; // 当前分数 int g_highScore; // 历史最高分（游戏关闭前有效） int g_state; // 游戏状态：0/1/2（对应MENU/PLAYING/GAMEOVER） int g_enemySpawnTimer; // 敌机生成倒计时，每帧+1，到spawnRate就生成 int g_enemySpawnRate; // 敌机生成间隔（帧），初始45，随分数减小 int g_frameCount; // 程序启动以来经过的总帧数，驱动所有动画

g_ 前缀是什么？匈牙利命名法——g 代表 global（全局）。一眼就能看出这是全局变量，不是函数内的局部变量。

g_frameCount 有什么作用？驱动动画周期。比如无敌闪烁用的是 `(g_frameCount/6)%2==0`——每6帧翻转一次可见性。引擎火焰用的是 `g_frameCount%10`——0到9循环，火焰长度周期性变化。如果没有全局帧号，每个动画都得自己维护一个计数器。

第 47-48 行

static int imin(int a,int b){return a<b?a:b;} static int imax(int a,int b){return a>b?a:b;}

为什么叫 imin 不叫 min？因为 Windows.h 已经把 min 和 max 占成宏了。虽然第1行定义了 NOMINMAX 阻止它们，但为了绝对安全，我还是用 imin/imax 避开所有可能的命名冲突。i 前缀表示 integer——只处理整数的 min/max。

static 是干嘛的？限制函数作用域——这两个函数只在当前 .cpp 文件内可见，不会和其他文件的同名函数冲突。虽然没有其他文件，但加 static 是好习惯。

第 50-56 行 — initStars()

void initStars(){ for(int i=0; i<MAX_STARS; i++){ g_stars[i].x=(float)(rand()%WINDOW_WIDTH); // ① X坐标：0到719随机 g_stars[i].y=(float)(rand()%WINDOW_HEIGHT); // ② Y坐标：0到959随机 g_stars[i].speed=rand()%3+1; // ③ 速度：1,2,3随机（3最快=近星） g_stars[i].bright=rand()%156+100; // ④ 亮度：100~255随机 } }

rand()%WINDOW_WIDTH 是什么意思？rand() 返回 0~32767 的随机整数，%720（取模）把它限制到 0~719。配合窗口宽度刚好覆盖全屏。+ (float) 强制类型转换——因为 x 和 y 字段是 float 类型。

speed 1/2/3 的设计意图？三层视差滚动。speed=1 的星最慢→给人"很遥远"的感觉；speed=3 的星最快→"比较近"。画的时候，近星更亮更大，远星更暗更小。三层的组合让星空有纵深感，不是平板一张。这是游戏开发里最古老也最好用的背景技巧。

bright 为什么是 rand()%156+100 而不是 rand()%256？rand()%256 会产生 0~255，但速度1的远星亮度还要除以3，如果本来就只有 10 的亮度，一除就成 3 了——几乎看不见。+100 保证最小亮度 100，保证远星也能看到。

第 59-68 行 — initGame()

void initGame(){ g_player.x = WINDOW_WIDTH/2.0f; // ① 玩家X = 屏幕水平中心 g_player.y = WINDOW_HEIGHT-120.0f; // ② 玩家Y = 屏幕底部往上120像素 g_player.w = 50; g_player.h = 60; // ③ 碰撞体积：宽50高60 g_player.lives = MAX_LIVES; // ④ 3条命 g_player.invTimer = 60; // ⑤ 开局60帧无敌（新手保护） g_player.shootTimer = 0; // ⑥ 可以立即射击 for(int i=0;i<MAX_BULLETS;i++) g_bullets[i].active=0; // ⑦ 所有子弹标记为空闲 for(int i=0;i<MAX_ENEMIES;i++) g_enemies[i].active=0; // ⑧ 所有敌机标记为空闲 for(int i=0;i<MAX_PARTICLES;i++) g_particles[i].active=0; // ⑨ 所有粒子标记为空闲 g_score=0; // ⑩ 分数归零 g_enemySpawnTimer=0; // ⑪ 敌机生成倒计时归零 g_enemySpawnRate=45; // ⑫ 初始每45帧生成一架敌机 g_frameCount=0; // ⑬ 帧号归零 initStars(); // ⑭ 重新撒星星 }

为什么开局要60帧无敌？防止"开局杀"——敌机从屏幕顶出来时玩家还没反应过来就撞上了。给1秒的无敌时间让玩家有一个适应的缓冲。

initGame 什么时候被调用？三处：程序启动初始化一次、菜单按空格开始新游戏、结束画面按R重来、游戏中按Q回菜单后再按空格。

第 71-82 行 — 对象池的三个函数

Bullet* getFreeBullet(){ for(int i=0; i<MAX_BULLETS; i++) // 遍历整个子弹数组 if(!g_bullets[i].active) // active==0 → 这个槽位空闲 return &g_bullets[i]; // 返回这个槽位的地址！调用方直接往里填数据 return NULL; // 遍历完都找不到空闲的 → 池满了 }

!g_bullets[i].active 为什么不用 ==0？! 是逻辑非运算符，!0=1(真)，!1=0(假)。!active 等价于 active==0，但更简洁。这是 C 语言的惯用写法。

&g_bullets[i] 返回的是什么？取地址运算符 &——返回数组第 i 个元素的指针。调用方拿到这个指针后通过 b->x, b->y, b->active=1 直接修改数组里的数据，不需要复制任何东西。

三个 getFree 函数能合并成一个通用的吗？能。用一个函数接受数组指针、元素大小、数组长度，返回 void*。但那样需要在调用方做类型转换，代码可读性下降。三个独立函数的代码重复量很小（每人3行），换来的是类型安全和可读性。

第 85-88 行 — spawnBullet()

void spawnBullet(){ Bullet*b=getFreeBullet(); if(!b)return; // ① 申请槽位；没空位就算了 b->x=g_player.x; // ② 子弹X = 玩家当前X（子弹从飞机发出） b->y=g_player.y - g_player.h/2; // ③ 子弹Y = 玩家Y减去半个身高 = 机头位置 b->w=6; b->h=14; b->active=1; // ④ 碰撞体积：宽6高14；激活！ }

子弹怎么变成双发的？看 updatePlayer() 里的调用：

float sx = g_player.x; // 保存玩家当前 X g_player.x = sx-10; // 假装玩家往左偏10像素 spawnBullet(); // 发出左翼子弹（子弹X=玩家X-10） g_player.x = sx+10; // 假装玩家往右偏10像素 spawnBullet(); // 发出右翼子弹（子弹X=玩家X+10） g_player.x = sx; // 恢复玩家真实位置

这招好巧妙——不用给 spawnBullet 传参数，直接临时修改玩家坐标再改回来，两发子弹自然就偏左偏右。

第 89-97 行 — spawnEnemy()

void spawnEnemy(){ Enemy*e=getFreeEnemy(); if(!e)return; int r=rand()%100; // 0~99随机数，用于概率分布 if(r<70){ // r=0~69：70%概率 → 小敌机 e->type=ENEMY_SMALL; e->w=30;e->h=30; e->speed=rand()%3+3; e->hp=1; }else if(r<90){ // r=70~89：20%概率 → 中敌机 e->type=ENEMY_MEDIUM; e->w=40;e->h=40; e->speed=rand()%2+2; e->hp=2; }else{ // r=90~99：10%概率 → 大敌机 e->type=ENEMY_BIG; e->w=55;e->h=55; e->speed=1; e->hp=4; } e->x=(float)(rand()%(WINDOW_WIDTH-e->w)+e->w/2); // X随机但不超出边界 e->y=(float)(-e->h); // Y = 负的身高 = 从屏幕顶外飞入 e->active=1; }

rand()%100 的分布？rand()%100 返回 0~99，每个数字等概率。所以 r<70 的概率就是 70/100=70%。这样三种敌机的出现比例是 7:2:1。

WINDOW_WIDTH - e->w 是怎么回事？假设窗口宽 720，大敌机宽 55。如果 X 随机到 700，右半边就超出屏幕了。rand()%(720-55) 限制随机范围最大 665。加 e->w/2=27 后 X 范围是 27~692——敌机最左到 27、最右到 692，刚好不出界。

e->y = -e->h 是干嘛？大敌机高度 55，起始 Y = -55——在屏幕顶部外55像素。下落过程中逐渐进入画面，玩家看不到"凭空出现"的感觉。所有 2D 射击游戏都这么做。

第 98-107 行 — spawnExplosion() ⭐

void spawnExplosion(float x,float y,int count){ for(int i=0; i<count; i++){ // 生成 count 个粒子 Particle*p=getFreeParticle(); if(!p)break; // 申请槽位；池满了停止生成 p->x=x; p->y=y; // ① 粒子的起始位置 = 爆炸中心 float angle=(float)(rand()%360)*3.14159f/180.0f; // ② 随机角度 (度→弧度) float speed=(float)(rand()%5)+2.0f; // ③ 随机速度 2.0~6.0 p->vx=cosf(angle)*speed; // ④ X方向速度 = cos(角度)×速度 p->vy=sinf(angle)*speed; // ⑤ Y方向速度 = sin(角度)×速度 p->maxLife=rand()%20+15; // ⑥ 总寿命：15~35帧 (0.25~0.6秒) p->life=p->maxLife; // ⑦ 当前寿命初始 = 总寿命 p->active=1; // ⑧ 激活这个粒子 } }

角度为什么要乘 3.14159/180？计算机的三角函数（cosf, sinf）接受的是弧度制，不是角度制。0~360° 对应 0~2π 弧度。要把角度转成弧度：弧度 = 角度 × π / 180。π ≈ 3.14159。

cosf(angle)*speed 干了什么？cos 函数返回"单位圆上该角度对应的X坐标"。比如 angle=0° 时 cos=1.0(正右)、angle=90°时 cos=0(无水平分量)、angle=180°时 cos=-1.0(正左)。乘以 speed 之后：如果 speed=5、angle=0°，粒子往正右方以5像素/帧的速度飞。

为什么 speed 是 2.0~6.0 不是 0~5？+2.0 保证最小速度是2——太慢的话粒子像挂在空中一样，不像爆炸。这是多次调试后的经验值。

maxLife 为什么是 15~35？太短了（<10帧）看不出颜色渐变，太长了（>50帧）粒子飞到屏幕外面浪费性能。15~35是视觉效果和性能的平衡。

答辩时怎么说这5行？"spawnExplosion 是粒子系统的核心。每个粒子三个随机属性——发射方向、初速度、寿命。方向用三角函数拆成水平分量和垂直分量，寿命用来控制后续的颜色渐变。这是游戏特效最基础的实现方式。"

第 110-125 行 — updatePlayer()

void updatePlayer(){ if(KEY_DOWN('A')||KEY_DOWN(VK_LEFT)) g_player.x-=PLAYER_SPEED; // A或←：左移6像素 if(KEY_DOWN('D')||KEY_DOWN(VK_RIGHT)) g_player.x+=PLAYER_SPEED; // D或→：右移6像素 if(KEY_DOWN('W')||KEY_DOWN(VK_UP)) g_player.y-=PLAYER_SPEED; // W或↑：上移6像素 if(KEY_DOWN('S')||KEY_DOWN(VK_DOWN)) g_player.y+=PLAYER_SPEED; // S或↓：下移6像素

为什么 A 和 VK_LEFT 都检测？'A' 是字符键（ASCII=65），VK_LEFT 是虚拟键码（=37，对应键盘上的左箭头）。有些玩家习惯 WASD（PC 游戏玩家），有些习惯方向键（休闲玩家）。同时检测两种操作方式，不用教任何人改习惯。

g_player.x=(float)imax(g_player.w/2, imin(WINDOW_WIDTH-g_player.w/2, (int)g_player.x));

这一行很绕，拆开读：

① (int)g_player.x — 把玩家当前X坐标（float）截断成 int。

② imin(WINDOW_WIDTH - g_player.w/2, ①) — 取"右边界允许的最大X"和"玩家当前X"中较小的那个。WINDOW_WIDTH-w/2 = 720-25 = 695。如果玩家走到700，imin返回695（被拦住）。如果玩家在300，imin返回300（没事）。这就防止了飞机超出右边界。

③ imax(g_player.w/2, ②) — 取"左边界允许的最小X=25"和"②的结果"中较大的那个。如果②是10，imax返回25（被拦住）。如果②是300，imax返回300（没事）。这就防止了飞机超出左边界。

效果：玩家X被钳制在 [25, 695] 之间，永远不超出屏幕。

if(g_player.shootTimer>0) g_player.shootTimer--; // 冷却倒计时-1 if(KEY_DOWN(VK_SPACE) && g_player.shootTimer<=0){ // 空格按着 + 冷却完毕 float sx=g_player.x; // 备份当前X g_player.x=sx-10; spawnBullet(); // 左翼子弹 g_player.x=sx+10; spawnBullet(); // 右翼子弹 g_player.x=sx; // 恢复X g_player.shootTimer=SHOOT_CD; // 重置冷却=8帧 } if(g_player.invTimer>0) g_player.invTimer--; // 无敌倒计时-1 }

SHOOT_CD=8意味着什么？每8帧才能射击一次。8÷60≈0.13秒，一秒大约射7轮，每轮2发子弹=14发。没有冷却的话一秒60发。这个值可以调——数字越小射越快。

第 127-133 行 — updateBullets()

void updateBullets(){ for(int i=0; i<MAX_BULLETS; i++){ if(!g_bullets[i].active) continue; // 跳过不活跃的（绝大多数都是不活跃的） g_bullets[i].y -= BULLET_SPEED; // 往上飞（Y减小） if(g_bullets[i].y < -20) // 顶部外20像素 g_bullets[i].active = 0; // 回收这颗子弹 } }

continue 在这里非常关键：100颗子弹里，活跃的可能就5~10颗。continue 跳过后面的移动和边界检查，直接进入下一轮循环。没有 continue 的话，每次循环都要访问不活跃的子弹——100次全遍历比5次遍历慢20倍。

为什么是 -20 不是 0？Y=0 是屏幕顶部。多给20像素的缓冲——子弹飞出屏幕外一点点再回收，视觉上不会有子弹突然消失的感觉。

vy += 0.15f 模拟了什么？重力！抛出物体后，垂直速度在重力作用下不断向下偏转。粒子初始可能往上飞（vy是负的），但在重力作用下慢慢减速、变向、往下掉。0.15 是重力强度——越大粒子越快往下掉。这是一个非常简单的物理模拟。

第 169-173 行 — checkCollision() ⭐⭐⭐

int checkCollision(float x1,float y1,int w1,int h1, float x2,float y2,int w2,int h2){ float l1 = x1 - w1/2.0f, r1 = x1 + w1/2.0f; // 物体1左边界 = 中心X - 半宽 float t1 = y1 - h1/2.0f, b1 = y1 + h1/2.0f; // 物体1上边界 = 中心Y - 半高 // 物体1右边界 = 中心X + 半宽 // 物体1下边界 = 中心Y + 半高 float l2 = x2 - w2/2.0f, r2 = x2 + w2/2.0f; // 物体2四条边，同上 float t2 = y2 - h2/2.0f, b2 = y2 + h2/2.0f; return (l1 < r2 && r1 > l2 && // ① X轴重叠判断 t1 < b2 && b1 > t2); // ② Y轴重叠判断 }

一行一行解释：

l1 = x1 - w1/2.0f物体中心X往左走半个宽度 = 物体的最左边缘
r1 = x1 + w1/2.0f物体中心X往右走半个宽度 = 物体的最右边缘
t1 = y1 - h1/2.0f物体中心Y往上走半个高度 = 物体的最上边缘。注意屏幕坐标系Y轴向下，所以 t1 比 y1 小
b1 = y1 + h1/2.0f物体中心Y往下走半个高度 = 物体的最下边缘
l1 < r2物体1的左边在物体2的右边之左。如果这个都不成立（l1≥r2），说明物体1完全在物体2右边→不可能重叠
r1 > l2物体1的右边在物体2的左边之右。配合上一条→X轴方向上有重叠
t1 < b2 && b1 > t2同理，Y轴方向上有重叠
四个条件同时成立→ 碰撞！

答辩时如果老师让画图：画两个重叠的矩形，标上 l1/r1/t1/b1 和 l2/r2/t2/b2。然后分别指出X轴和Y轴的投影重叠情况。这是得分最高的部分。

srand((unsigned)time(NULL)) 是干嘛的？time(NULL) 返回从1970年1月1日到现在的秒数。把秒数当作随机种子喂给 srand()，之后 rand() 每次运行都会产生不同的序列。如果不调 srand，每次运行 rand() 返回的序列都是一模一样的——敌机每次都从同一个位置出来。

Sleep(16) 为什么是16？1000毫秒 ÷ 60帧 ≈ 16.67毫秒/帧。Sleep(16) 让每帧至少等16毫秒，帧率不会超过60FPS。没有这个 Sleep，主循环会疯狂旋转——每秒几百上千帧——吃满CPU，而且不同电脑上游戏速度不一样。

为什么 GAMEOVER 还要 updateStars 和 updateParticles？结束画面是静态的，但玩家死亡后的爆炸粒子需要继续扩散衰减，星星也需要继续滚动——保持画面有动感。不调的话粒子就停在死亡那一刻不动了，看着很怪。

goto 真的不丢人吗？不丢人。C 语言里 goto 用于跳到函数末尾的统一清理出口是标准做法。Linux 内核源码里大量使用了这种模式：`goto out;` / `goto err;`。丑的是用 goto 来来回回跳做控制流——那是面条代码。但 goto 做错误处理和资源清理非常干净。
